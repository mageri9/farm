# Shorts Generator

python generate.py --count 3 --category all

## 1. Назначение

Shorts Generator собирает вертикальные видео с озвучкой, фоновыми кадрами и встроенными субтитрами. Проект предназначен для подготовки коротких документальных роликов для Shorts, Reels и других площадок с вертикальным форматом.

Можно начать с собственного текста, готовой подборки фактов или поручить модели подбор тем. Программа создает MP4 и, в пакетных режимах, текстовый план публикаций с названиями, тегами и закрепленными комментариями. Загрузка роликов на площадки выполняется вручную.

По умолчанию результат имеет разрешение **1080x1920**, частоту **30 FPS**, видео **H.264** и звук **AAC**. Русская озвучка создается через Microsoft Edge TTS, субтитры показываются по два слова в центре кадра. При наличии нескольких фонов программа выбирает два и меняет план в середине ролика.

| Задача | Команда | Нужен ключ AnyModel |
| --- | --- | --- |
| Сделать один ролик из своего текста | `python main.py` | Нет |
| Подобрать факты, написать сценарии и собрать ролики | `python generate.py` | Да |
| Написать сценарии по локальному файлу фактов | `python fetch_content.py` | Да |
| Сделать пачку роликов из готовых сценариев | `python batch_generate.py` | Нет |

AI-сценарии проходят проверку длины в 45–55 слов. Это ориентир для короткого ролика примерно на 25 секунд: фактическая длительность определяется озвучкой, выбранным голосом и скоростью речи.

## 2. Полный пользовательский гайд

### 2.1. Требования

- Python 3.11 или новее.
- FFmpeg и ffprobe. Сборка FFmpeg должна включать кодировщик `libx264` и фильтр `subtitles` с поддержкой libass.
- Интернет для синтеза речи Edge TTS.
- Ключ AnyModel и доступ к его API для `generate.py` и `fetch_content.py`.
- Один или несколько фоновых MP4 и место для готовых и временных файлов.

Примеры ниже предназначены для Windows PowerShell. Выполняйте команды из корня проекта. Фоновые видео, шрифты, локальные EXE, `.env` и результаты исключены из Git, поэтому после клонирования их нужно подготовить отдельно.

### 2.2. Установка

Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активируйте окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

Далее `python` означает Python из этого окружения. Если PowerShell запрещает запуск скрипта активации, используйте вместо `python` полный относительный путь `.\.venv\Scripts\python.exe`; активация для этого не нужна.

Поместите `ffmpeg.exe` и `ffprobe.exe` в корень проекта или добавьте каталог с ними в `PATH`. Программа сначала ищет инструменты через `PATH`, затем в корне проекта. `ffplay.exe` для генерации не требуется.

Проверка локальных EXE:

```powershell
.\ffmpeg.exe -version
.\ffprobe.exe -version
.\ffmpeg.exe -filters | Select-String subtitles
.\ffmpeg.exe -encoders | Select-String libx264
```

Если инструменты установлены через `PATH`, используйте те же команды без `.\`.

### 2.3. Фоновые видео и шрифты

Создайте каталог фонов:

```powershell
New-Item -ItemType Directory -Force assets\backgrounds
```

Положите в него MP4, например:

```text
assets/
  backgrounds/
    gameplay_01.mp4
    gameplay_02.mp4
  fonts/
    Montserrat-Bold.ttf
```

Порядок выбора фона:

1. Если в `assets/backgrounds/` есть MP4, используются только файлы из этой папки.
2. Иначе программа ищет MP4 непосредственно в `assets/`.
3. Если оба набора пусты, используется путь `background` из настроек; по умолчанию это `assets/background.mp4`.

Поиск не рекурсивный. Если найден один файл, он используется на всю длительность речи. Если файлов два или больше, случайно выбираются два разных фона, каждый примерно на половину ролика; переход между ними — обычный стык.

Короткие фоны зацикливаются. Для одного файла это управляется настройкой `loop_background` и включено по умолчанию; в режиме двух планов зацикливание включено всегда.

Используйте горизонтальный фон или видео не уже формата 9:16. Программа вырезает центральную область 9:16 и масштабирует ее до выходного разрешения: значимые объекты у боковых краев могут исчезнуть. Исходный звук фона не попадает в результат — остается только озвучка.

Шрифт по умолчанию — Montserrat, размер — 80 в системе координат субтитров 1080x1920. Можно положить `.ttf`/`.otf` в `assets/fonts/` или использовать установленный шрифт. Если Montserrat недоступен, libass подберет замену. Выбор имени шрифта описан в разделе настроек.

### 2.4. Проверка первого ролика

Для своего текста ключ AnyModel не нужен:

```powershell
python main.py --text "Это первый тестовый ролик. Программа добавляет озвучку, фоновое видео и синхронные субтитры."
```

По завершении программа напечатает путь к MP4, разрешение, FPS, длительность и аудиокодек. Без явно заданного имени результат сохраняется как `output/final_<uuid>.mp4`.

### 2.5. Один ролик из своего текста

```powershell
python main.py "Текст истории для озвучки."
python main.py --input input\story.txt --output output\story.mp4
python main.py --text "Еще один тестовый текст." --voice ru-RU-SvetlanaNeural --rate "+5%" --fps 60
python main.py --input input\story.txt --seed 123 --keep-work
```

Текстовый файл должен быть в UTF-8 без BOM. Допустимая длина текста после удаления пробелов по краям — от 3 до 20 000 символов. Ограничение AI-сценариев в 45–55 слов к этому режиму не применяется.

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| Позиционный текст | — | Текст после имени скрипта |
| `--text` | — | Явно заданный текст |
| `--input` | — | Прочитать текст из файла |
| `--output` | `output/final_<uuid>.mp4` | Путь к MP4 |
| `--voice` | `ru-RU-DmitryNeural` | Голос Edge TTS |
| `--rate` | `+10%` | Скорость речи относительно обычной |
| `--fps` | `30` | 30 или 60 кадров в секунду |
| `--seed` | Не задан | Повторяемый выбор фоновых файлов и смещений при одинаковых исходных условиях |
| `--keep-work` | Выключен | Сохранить MP3 и ASS в `work/run_<id>/` |

При одновременном указании способов ввода `--input` имеет приоритет, затем непустой `--text`, затем позиционный текст. Относительный путь входного файла считается от текущей папки, выходного MP4 — от корня проекта.

Для отрицательной скорости используйте запись `--rate=-5%`. Выходной файл должен иметь расширение `.mp4`. Если такой файл уже существует, успешный запуск заменит его.

### 2.6. Настройка AnyModel

Для подбора фактов и написания сценариев создайте `.env` в корне проекта и добавьте:

```dotenv
ANYMODEL_API_KEY=your_api_key_here
```

Если `.env` уже существует, отредактируйте нужные строки, сохранив остальные настройки. Уже заданные переменные окружения имеют приоритет над значениями из `.env`.

Модель по умолчанию — `ag/gemini-3.7-flash-medium`. Переменные `PRIMARY_MODEL` и `FALLBACK_MODEL` задают основную и резервную модели (`ANYMODEL_MODEL` остается совместимым алиасом для основной). Основная модель получает две попытки; после transient-ошибок выполняется один запрос резервной моделью. Ошибки формата запроса и программные ошибки повторно не отправляются.

Оба скрипта отправляют данные в API AnyModel. Режим `--dry-run` тоже выполняет запросы к модели.

### 2.7. Автоматический подбор фактов и генерация

```powershell
python generate.py
python generate.py --count 6 --category all
python generate.py --count 2 --category systems --voice ru-RU-SvetlanaNeural --fps 60
```

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `--count` | `3` | Положительное число фактов и роликов |
| `--category` | `all` | Категория из таблицы ниже |
| `--dry-run` | Выключен | Подобрать факты и сохранить сценарии без озвучки и видео |
| `--voice` | `ru-RU-DmitryNeural` | Голос озвучки |
| `--rate` | `+10%` | Скорость речи |
| `--fps` | `30` | 30 или 60 FPS |

| Категория | Тематика |
| --- | --- |
| `systems` | Инженерные ошибки, инфраструктура, авиация, программные и аппаратные сбои |
| `science` | Космос, физика и природные явления |
| `mind` | Восприятие, когнитивные эффекты и эксперименты |
| `all` | Чередование `systems`, `science`, `mind` по кругу |

Порядок работы: проверка окружения, запрос всей подборки фактов, сохранение фактов, последовательная подготовка всех сценариев, затем последовательный рендер.

Факты и ссылки предлагает модель. Программа проверяет структуру ответа, наличие обязательных полей и корректность формата URL, но не скачивает источники и не сверяет с ними утверждения. Перед публикацией проверьте содержание и ссылки из `facts.json`.

Каждый запуск создает отдельную папку `output/batch_YYYYMMDD_HHMMSS/`:

| Файл | Содержимое |
| --- | --- |
| `facts.json` | Факты с датами, местами, числами, ключевыми словами и источниками |
| `story_01.txt`, … | Тексты для озвучки |
| `stories.json` | Сценарии, метаданные, имена видео и статусы |
| `video_01.mp4`, … | Успешно собранные ролики |
| `posting_plan.txt` | Названия, теги, закрепленные комментарии и статусы |
| `render.jsonl` | События озвучки и рендера; создается в режиме с видео |
| `batch_result.json` | Статус `SUCCESS`, `PARTIAL_SUCCESS` или `FAILED`, счетчики и безопасные ошибки элементов |
| `error.json` | Ошибка подготовки общей части пачки, если папка уже создана |

Статус сценария: `dry-run`, `pending`, `rendered` или `failed`. У успешно отрендеренного сценария появляется `report`, у неудачного — `error`.

Ошибка общей подготовки фактов останавливает запуск. Ошибка отдельного факта или рендера сохраняется с номером элемента, этапом и traceback, после чего программа продолжает остальные элементы. Exit code `1` сохраняется для частичного и полного отказа.

### 2.8. Проверить сценарии до рендера

```powershell
python generate.py --count 3 --category all --dry-run
```

Этот режим не требует фоновых видео и FFmpeg, не вызывает Edge TTS, но требует ключ AnyModel. Он сохраняет факты, сценарии и план публикаций. MP4 не создаются, хотя их будущие имена присутствуют в плане.

Откройте тексты и источники, внесите правки в `stories.json`, затем передайте его пакетному рендереру, подставив имя созданной папки:

```powershell
python batch_generate.py --input output\batch_YYYYMMDD_HHMMSS\stories.json
```

Рендер создаст новую папку пачки. Он не обновляет статусы в исходном `stories.json`.

История тем хранится в `work/facts_history.json`. Подбор фактов записывается туда **до подготовки сценариев и рендера, в том числе при `--dry-run`**. После ошибки темы остаются в истории. Чтобы повторно использовать уже сохраненные материалы, рендерите их через `batch_generate.py`, а не запускайте новый подбор.

### 2.9. Сценарии из своего файла фактов

`fetch_content.py` адаптирует локальные факты, не выполняя их автоматический подбор. По умолчанию читает `seed_facts.json`.

Формат входа — непустой JSON-массив объектов:

```json
[
  {
    "title": "Название события",
    "raw_data": "Подробное описание проверенного события: что произошло, где, когда и с каким результатом.",
    "category": "systems"
  }
]
```

Заполните `title` и `raw_data` своими данными. Если заголовок отсутствует, используется «Факт N»; категория необязательна и по умолчанию равна `general`. Дополнительные поля, например `topic`, этот скрипт не переносит в результат.

```powershell
python fetch_content.py
python fetch_content.py --facts input\facts.json --output input\stories.json
python fetch_content.py --model "идентификатор_доступной_модели"
```

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `--facts` | `seed_facts.json` в корне проекта | JSON-файл фактов, UTF-8 без BOM |
| `--output` | `input/stories.json` в корне проекта | Куда записать сценарии |
| `--model` | `PRIMARY_MODEL` / `ANYMODEL_MODEL` или встроенная модель | Явная основная модель адаптации; резервная задается `FALLBACK_MODEL` |

Явно заданные относительные пути считаются от текущей папки. В JSON попадают только успешно адаптированные истории; ошибочный элемент не прерывает обработку. Скрипт возвращает `1` при частичном или полном отказе и `0`, только если обработаны все элементы. История `facts_history.json` в этом режиме не используется.

### 2.10. Пакетный рендер готовых сценариев

Минимальный входной файл:

```json
[
  {
    "title": "Первый ролик",
    "text": "Этот текст будет озвучен и показан в субтитрах.",
    "tags": ["#факты", "#история", "#шортс"]
  },
  {
    "text": "Второй сценарий можно передать без заголовка и тегов."
  }
]
```

Верхний уровень — непустой массив. Каждая история должна быть объектом с непустой строкой `text`; действует лимит конвейера в 3–20 000 символов. `title` и `tags` нужны для плана публикаций и не озвучиваются. Дополнительные поля игнорируются. Файл читается как UTF-8, включая UTF-8 с BOM.

```powershell
python batch_generate.py
python batch_generate.py --input input\stories.json --output-dir output --fps 60
```

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `--input` | `input/stories.json` | JSON-массив сценариев |
| `--output-dir` | `output` | Базовая папка результатов |
| `--voice` | `ru-RU-DmitryNeural` | Голос |
| `--rate` | `+10%` | Скорость речи |
| `--fps` | `30` | Поддерживаются 30 и 60 FPS |
| `--channel-tag` | `@reddit_vault` | Принимается CLI, но в текущем коде не влияет на план публикаций |

Относительные пути считаются от корня проекта. Внутри базовой папки создается `batch_YYYYMMDD_HHMMSS` с видео и `posting_plan.txt`. План содержит только успешные ролики. Нумерация соответствует позиции во входном массиве, поэтому после ошибок возможны пропуски.

Не запускайте две копии `batch_generate.py` в одну базовую папку в одну секунду: имя каталога строится только по времени и может совпасть. Для независимых запусков укажите разные `--output-dir`.

### 2.11. Настройки изображения, звука и таймаутов

`generate.py` читает настройки `SHORTS_*` из окружения и `.env`. `main.py` и `batch_generate.py` создают `Settings` напрямую, поэтому эти переменные в них **не применяются**: используйте доступные CLI-аргументы или меняйте значения по умолчанию в `src/config.py`.

Пример дополнительных строк `.env` для `generate.py`:

```dotenv
SHORTS_FONT_NAME=Montserrat
SHORTS_FONT_SIZE=80
SHORTS_WORDS_PER_SUBTITLE=2
SHORTS_CRF=22
SHORTS_PRESET=veryfast
SHORTS_RENDER_TIMEOUT=1800
SHORTS_CLEANUP_WORK=false
```

| Поле Settings / переменная | По умолчанию | Значение |
| --- | --- | --- |
| `font_name` / `SHORTS_FONT_NAME` | `Montserrat` | Имя семейства шрифта |
| `font_size` / `SHORTS_FONT_SIZE` | `80` | Размер текста субтитров |
| `words_per_subtitle` / `SHORTS_WORDS_PER_SUBTITLE` | `2` | Слов в одной группе |
| `video_width`, `video_height` / `SHORTS_VIDEO_WIDTH`, `SHORTS_VIDEO_HEIGHT` | `1080`, `1920` | Четные размеры, минимум 2 |
| `crf` / `SHORTS_CRF` | `22` | Качество H.264, 0–51; меньше — выше качество и обычно больше файл |
| `preset` / `SHORTS_PRESET` | `veryfast` | Пресет кодирования FFmpeg |
| `audio_bitrate` / `SHORTS_AUDIO_BITRATE` | `192k` | Битрейт AAC |
| `background` / `SHORTS_BACKGROUND` | `assets/background.mp4` | Резервный фон, если оба каталога MP4 пусты |
| `loop_background` / `SHORTS_LOOP_BACKGROUND` | `true` | Зацикливать одиночный фон |
| `cleanup_work` / `SHORTS_CLEANUP_WORK` | `true` | Удалять временную папку запуска |
| `ffmpeg`, `ffprobe` / `SHORTS_FFMPEG`, `SHORTS_FFPROBE` | `ffmpeg`, `ffprobe` | Имена или пути к инструментам |
| `probe_timeout` / `SHORTS_PROBE_TIMEOUT` | `30` | Таймаут одного ffprobe, секунды |
| `render_timeout` / `SHORTS_RENDER_TIMEOUT` | `1800` | Таймаут одного рендера, секунды |
| `tts_timeout` / `SHORTS_TTS_TIMEOUT` | `30` | Таймаут одной попытки озвучки, секунды |
| `retry_attempts` / `SHORTS_RETRY_ATTEMPTS` | `3` | Попытки TTS, от 1 до 10 |
| `retry_delay` / `SHORTS_RETRY_DELAY` | `3` | Начальная задержка повторов TTS, от 0 до 60 секунд |
| `max_text_chars` / `SHORTS_MAX_TEXT_CHARS` | `20000` | Максимальная длина текста |

Булевы значения принимают `true`, `false`, `1` или `0`. Таймауты должны быть положительными конечными числами.

Голос, скорость и FPS задавайте через `--voice`, `--rate`, `--fps`: в `generate.py` даже значения этих CLI-аргументов по умолчанию перекрывают `SHORTS_VOICE`, `SHORTS_RATE` и `SHORTS_FPS`. Корень проекта также передается этим скриптом явно и перекрывает `SHORTS_ROOT`.

Поле `request_timeout` / `SHORTS_REQUEST_TIMEOUT` существует (по умолчанию 60), но не подключено к AI-клиентам: они создаются с таймаутом 90 секунд.

### 2.12. Ошибки, повторный запуск и сохраненные файлы

| Сообщение или ситуация | Что проверить или сделать |
| --- | --- |
| `FFmpeg was not found` | Наличие обоих инструментов в `PATH` или корне проекта |
| `No MP4 in ...` | Фоновые файлы в `assets/backgrounds/`, `assets/` или по резервному пути |
| `Text must contain 3-20000 characters` | Длину текста после удаления пробелов по краям |
| `Output must have an .mp4 extension` | Расширение выходного файла |
| `TTS failed after ... attempts` | Интернет, доступность Edge TTS, имя голоса и скорость; затем повторите запуск |
| `no WordBoundary events` | Сервис не вернул тайминги слов; генерация субтитров без них прекращается |
| `FFmpeg render failed` | Последние строки ошибки FFmpeg: исправность видео, поддержку фильтров/кодеков и параметры кадрирования |
| `FFmpeg exceeded ... seconds` | Увеличьте таймаут рендера применимым к вашему режиму способом |
| `Output validation failed` | Разрешение, FPS, кодеки и длительность; при отключенном зацикливании одиночный фон может оказаться коротким |
| `Не задан ANYMODEL_API_KEY` | Ключ в `.env` или окружении |
| `Already used` | Модель вернула тему или ключевое слово из истории; новый запрос может подобрать другой факт |
| Ошибка чтения истории | Проверьте JSON в `work/facts_history.json`; поврежденная история автоматически не перезаписывается |
| `Another process is using this job` | Дождитесь завершения процесса, работающего с тем же выходным файлом или историей |

При обычном завершении, включая обработанную ошибку, папка `work/run_<id>/` удаляется. Для диагностики используйте `main.py --keep-work` или `SHORTS_CLEANUP_WORK=false` с `generate.py`: внутри останутся `audio.mp3` и `subtitles.ass`, если их удалось создать.

Файлы `.lock` могут оставаться после завершения работы. Блокировка удерживается операционной системой, поэтому наличие такого файла само по себе не означает, что задача еще выполняется. После аварийного завершения процесса могут также остаться временные файлы.

Автоматического продолжения прерванной пачки нет. Для повторного рендера отдельного сценария используйте:

```powershell
python main.py --input output\batch_YYYYMMDD_HHMMSS\story_01.txt --output output\retry_01.mp4
```

Коды завершения: `0` — успех, `1` — ошибка генерации или частичный сбой рендера, `2` — ошибка аргументов или некоторые ошибки входных файлов/настройки. У `fetch_content.py` есть описанная выше особенность частичного успеха. `generate.py` обрабатывает Ctrl+C и возвращает `130`; уже записанные результаты остаются в `output/`.

`src/content/reddit.py` не вызывается ни одним из текущих четырех CLI-скриптов.

Зависимости: `edge-tts>=6.1.0`, `httpx>=0.27.0`, `openai>=1.40.0`, `pydantic>=2.0.0`, `python-dotenv>=1.0.0`. SDK `openai` используется как клиент совместимого API AnyModel с `base_url="https://anymodel.org/v1"`. FFmpeg запускается отдельным процессом.

### 3.2. Конвейер одного ролика

`ShortsPipeline.run(text, output_path=None, seed=None)` возвращает путь к готовому MP4. После успешной проверки `last_report` содержит `duration`, `fps` и `audio_codec`.

1. Проверяются длина текста, доступность FFmpeg/ffprobe и наличие фоновых файлов.
2. Выходной путь приводится к абсолютному; проверяется расширение MP4 и захватывается блокировка `<имя>.mp4.lock`.
3. Создается отдельный каталог `work/run_<id>/`.
4. Edge TTS потоково записывает MP3 на диск и возвращает события границ слов.
5. Тайминги группируются в ASS-субтитры; ffprobe определяет длительность аудио.
6. Выбираются один или два фона и начальные смещения.
7. FFmpeg создает скрытый временный `.<имя>.<uuid>.partial.mp4` рядом с целевым файлом.
8. ffprobe проверяет результат, после чего `os.replace` заменяет конечный MP4.
9. В блоке `finally` удаляется незавершенный MP4 и, если включена очистка, каталог запуска.

Python не загружает видеокадры в память. Сетевые операции асинхронные, но FFmpeg/ffprobe вызываются синхронно через `subprocess.run`; ролики внутри одной пачки обрабатываются последовательно.

### 3.3. Озвучка и субтитры

`generate_tts()` преобразует `offset` и `duration` событий Edge TTS из интервалов по 100 нс в секунды. Возвращается список `WordBoundary(word, start, end)`. Пустое аудио или отсутствие корректных границ слов считается ошибкой.

`write_ass()` объединяет последовательные слова в группы. Начало реплики — начало первого слова, конец — конец последнего. Время ASS округляется до сотых секунды. Спецсимволы текста и пути фильтра экранируются отдельно.

Стиль по умолчанию: белый жирный текст, черная обводка толщиной 8, тень 2, выравнивание по центру. Система координат ASS фиксирована на 1080x1920. Субтитры встраиваются в изображение и не являются отключаемой дорожкой MP4.

### 3.4. Обработка видео и проверка результата

Для каждого фона применяется центральное кадрирование до 9:16, масштабирование, квадратный пиксель, заданный FPS и сброс временных меток. Два плана обрезаются по длительности и соединяются фильтром `concat`, затем добавляются субтитры.

Кодирование: `libx264`, `crf=22`, `preset=veryfast`, `yuv420p`; звук — `aac`, `192k`. `+faststart` переносит служебные данные MP4 в начало файла. Длительность ограничивается длиной озвучки и параметром `-shortest`.

`validate_output()` проверяет наличие непустого файла, видеопотока нужного размера, аудиопотока, кодеков H.264/AAC, положительной конечной длительности и заданного FPS. Допуск отклонения длительности от аудио — 0,5 секунды, FPS — 0,5 кадра/с. Эта проверка не оценивает содержание речи или визуальную читаемость субтитров.

### 3.5. Подбор фактов и адаптация сценариев

`FactResearcher` запрашивает всю подборку одним сообщением и проверяет точное число объектов, порядок категорий и модель `ResearchedFact`:

| Поле | Проверка |
| --- | --- |
| `topic`, `title` | Не менее 3 символов |
| `category` | `systems`, `science` или `mind` |
| `raw_data` | Не менее 30 символов |
| `date` | Содержит четырехзначный год |
| `location` | Не менее 2 символов |
| `systems`, `keywords` | Непустые списки непустых строк |
| `figures` | Непустой список; каждый элемент содержит цифру |
| `sources` | 1–3 объекта с заголовком и URL формата HTTP/HTTPS |

Промпт требует первичные источники и HTTPS, но валидатор URL допускает также HTTP. Доступность ссылок и фактическая достоверность автоматически не проверяются.

Дедупликация сравнивает пересечения нормализованных `topic` и `keywords`: Unicode NFKC, приведение регистра, выделение слов. Это сопоставление строк, а не семантическая проверка одинаковых событий. История перечитывается под блокировкой и обновляется атомарно только после проверки всей подборки.

`StoryAdapter` получает название и фактуру, запрашивает JSON с `title`, `text`, `tags` и проверяет `AdaptedStory`. Текст должен содержать 45–55 слов без цифр; слова считаются через `split()`. Заголовок непустой, до 10 слов, хотя промпт просит до 5. Теги очищаются, получают префикс `#` и приводятся к 3–5 элементам.

При ошибке формата или валидации ответ возвращается модели с просьбой исправить его; всего до трех попыток. Если исправление не удалось или возникла другая ошибка запроса, адаптер возвращает `None`.

### 3.6. Отказоустойчивость и журналирование

TTS повторяется до `retry_attempts` раз, с таймаутом на попытку и экспоненциальной задержкой `retry_delay * 2^attempt`, ограниченной 60 секундами. После исчерпания попыток для голоса `ru-RU-DmitryNeural` выполняется одна попытка `ru-RU-SvetlanaNeural`; частичный аудиофайл не публикуется.

Исследователь и адаптер используют общий bounded-механизм: две попытки основной модели, затем одна резервной при `APIConnectionError`, timeout, сетевых ошибках, HTTP 429 и 5xx; встроенные повторы SDK отключены. Невалидный JSON, неверное число фактов, дубликаты и ошибки программирования не запускают fallback. В пакетах каждый элемент имеет собственную границу ошибки; результат записывается как `SUCCESS`, `PARTIAL_SUCCESS` или `FAILED`, а `posting_plan.txt` содержит только успешно созданные видео.

`atomic_text()` и `atomic_json()` записывают временный файл в том же каталоге, выполняют `flush`/`fsync` и `os.replace`. `generate.py` использует их для промежуточных результатов. `fetch_content.py` записывает выходной JSON, а `batch_generate.py` — план публикаций обычной записью файла.

Блокировки используют `msvcrt` в Windows и `fcntl` на других системах. Операционная система освобождает блокировку при завершении процесса; файл блокировки сохраняется.

В `generate.py` журнал `render.jsonl` содержит UTC-время, уровень, имя события и дополнительные поля. Основные события: `tts.started`, `tts.failed`, `tts.completed`, `render.started`, `render.completed`, `work.retained`. `safe_error()` сокращает сообщения и маскирует значения переменных окружения с именами, содержащими `KEY`, `TOKEN`, `PASSWORD` или `SECRET`.

### 3.7. Проверки и разработка

Запуск модульных тестов:

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют настройки, субтитры, выбор фоновых файлов, построение команд FFmpeg, валидацию сценариев и фактов, историю и обработку ошибок API. Внешние вызовы в этих проверках заменяются заглушками; для проверки реального окружения используйте короткий запуск из раздела 2.4.

В текущем наборе есть устаревший `tests/test_fetch_content.py`: он импортирует отсутствующую в `fetch_content.py` константу `AI_TOPICS`. Поэтому полный запуск тестов требует актуализации этого теста под нынешний файловый ввод фактов.
